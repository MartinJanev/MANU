Deviations and best guesses (`load()` and `_score()` were not run on a GPU or with the real weights):
- Model name: the script's default `--model clip-vit_large-scan_study-dualdinotxt1568` (the README command passes none) is not a key of `_MODEL_CONFIGS`: the keys are the JSON file stems and open_clip 3.3.0's `get_model_config` does not map hyphens to underscores, so that command as written stops with "Model config … not found". `load()` uses the file stem `clip_vit_large_scan_study_dualdinotxt1568`.
- `pretrained_text=False` (the script keeps open_clip's default True). With True, the text tower calls `AutoModel.from_pretrained(BiomedBERT)`; if that repo has only `pytorch_model.bin`, transformers 4.57.6 refuses to `torch.load` it unless `version.parse(torch) >= 2.6` (`check_torch_load_is_safe`), and the image's `2.6.0a0+…` compares lower. With False the text tower is built from BiomedBERT's `config.json` (`AutoModel.from_config`), and every text weight comes from the strict `load_state_dict` of the HLIP checkpoint, which replaced the BiomedBERT weights in the original script too. The image tower is never initialised from the MAE ViT-L weights named in `visual_encoder.py`: open_clip 3.3.0 sets `timm_model_pretrained` to its `pretrained_image` argument (default False).
- Classes and template (task brief): one template, `TEMPLATES[1]` of `zeroshot_metadata_pubbrain5.py`, "This study shows: {c} identified.", whose wording for the normal class is "This study shows: no significant abnormalities." (kept), instead of the average over the 18 templates the script uses. One softmax over 15 classes copied verbatim, in file order: the 5 Pub-Brain-5 classes and the 10 MR-RATE classes that fit a group. The mapping is `CLASS_GROUPS` in `run.py`: normal = "no significant abnormalities"; tumor = "glioma", "meningioma", "metastasis", "Metastatic malignant neoplasm to brain", "Intracranial meningioma", "Schwannoma", "Glioma", "Pituitary adenoma"; stroke = "acute stroke", "Cerebral infarction", "Cerebral hemorrhage", "Lacunar infarct", "Watershed infarct"; multiple sclerosis = "Demyelinating disease of central nervous system". `diagnosis_name` is the group with the largest summed probability, `diagnosis_confidence` that sum. The groups have 1, 8, 5 and 1 classes, so the sum favours tumor and stroke when the classes score alike (compare the blank controls).
- MR-RATE classes left out (no group fits): Herniation of nucleus pulposus, Spinal cord compression, Silent micro-hemorrhage of brain, Cavernous hemangioma, Subdural intracranial hemorrhage, Gliosis, Cerebral atrophy, Encephalomalacia, Arachnoid cyst, Empty sella syndrome, Intracranial aneurysm, Chiari malformation, Cyst of pineal gland, Hemangioma of vertebral column, Rathke's pouch cyst, Cerebral edema, Spinal stenosis, Mastoiditis, Chronic mastoiditis, Ventriculomegaly, Cerebellar degeneration, Mega cisterna magna, Structure of cave of septum pellucidum, Hyperostosis of skull, Choroid plexus cyst, Foraminal Spinal Stenosis, Lipoma of brain.
- `torch.load` of the checkpoint is called as in the script, whose README installs torch 2.5.1 (`weights_only` defaults to False there); if the image's torch defaults to `weights_only=True`, a checkpoint holding objects other than tensors and plain containers fails to load (the upload script in `hlip-ablation` saves a plain dict of tensors).
- One scan per study (T1 only, `[1, 1, 1, 48, 224, 224]`); HLIP's study attention was trained and evaluated on all scans of a study (Pub-Brain-5's BraTS studies have four).
- Softmax in float32 (the script takes it on the float16 logits).
- Preprocessing (`preprocess`, numpy only): `to_model_axes`, then the image steps of `PubBrain5Dataset.__getitem__` applied to the `to01` output in place of the stored uint8 / 255: zero padding of H and W to a square, `F.interpolate(size=(256, 256), mode='bilinear')` (align_corners False), `F.interpolate(size=(48, 256, 256), mode='nearest-exact')`, crop 16:240, `Normalize(0.449, 0.226)` (mean of the ImageNet mean/std). Checked against torch 2.6.0 (CPU) running the script's lines (after the same axis flips) on 8 shapes from (7, 33, 17) to (300, 200, 200) and on the BraTS example: largest absolute difference 9.5e-7 (float32 rounding), same slice selection; `test_preprocess_matches_torch_steps` keeps two of these reference results.
- Axis order: every Pub-Brain-5 script reorients with SimpleITK `DICOMOrientImageFilter` to 'RPI' and takes `GetArrayFromImage`: depth head → feet, rows front → back, columns patient left → right (the Stroke script's nibabel loader for DWI, `transpose_raw2rpi`, gives the same layout). Our canonical stack runs feet → head, front → back, right → left, so `to_model_axes` reverses depth and columns (`vol[::-1, :, ::-1]`). Checked with SimpleITK 2.5.7 on six NIfTI affines (RAS, LPS, two other flips, sagittal, permuted): HLIP's array equals `load_canonical(path)[::-1, :, ::-1]` every time; `test_volume_is_in_hlip_loader_axes` keeps the nibabel form of it. The BraTS example in `docs/` agrees (vertex first, anterior at the top). The Open-BHB, Stroke, NYUMets and UCSFMets scripts also transpose the axis with the largest spacing to depth (`transpose2dhw`), so HLIP would read a sagittal IXI scan as a sagittal stack; we keep the axial stack for every dataset (global constraints).
- Intensities: the Pub-Brain-5 scripts clip each scan to its 0.5/99.5 percentiles, scale to [0, 1] and (`--uint8`) store `img * 255` as uint8, which `zeroshot_pubbrain5.py` divides by 255. `to01` does the same for MRI (`normalize01`, 0.5/99.5 percentiles over the whole volume) without the uint8 rounding; CT-RATE gets the [-1000, 1000] HU window. BraTS scans are skull-stripped; IXI, MOLAB and open_ms_data T1 are not.
- CPU smoke test (scratch venv: torch 2.6.0, torchvision 0.21.0 and the pins below; a stand-in BERT-base config and vocabulary in place of BiomedBERT; a snapshot holding the state dict of a freshly built model; device cpu, bfloat16 autocast): `load()` and `_score()` run end to end (model built from the HLIP clone with timm 1.0.26, strict `load_state_dict`, classifier 768x15, forward on `[1, 1, 1, 48, 224, 224]`, 15 probabilities summing to 1). Not tested: the real checkpoint's keys, BiomedBERT's files, CUDA.

Pins (`requirements.txt`; the README names no versions; `pip check` clean with torch 2.6.0 / torchvision 0.21.0):
- open_clip_torch==3.3.0 (2026-02-26): the last release before open_clip's main branch became 4.0.0.dev0 (2026-02-27), whose task refactor removed Horovod and on 2026-04-28 raised the requirement to torch>=2.6, which the image's 2.6.0a0 does not meet. `zeroshot_pubbrain5.py` still passes the `--horovod` argument that 3.x's `open_clip_train.distributed` reads. Requires torch>=2.0, timm>=1.0.17.
- timm==1.0.26 (2026-03-23): the timm release current when HLIP's 2026-04 models and code came out; has `timm.models.checkpoint` (imported by `visual_encoder.py`) and the `VisionTransformer` arguments it uses (`pos_embed='none'`, `reg_tokens`, `no_embed_class`, `embed_layer`). Requires torch (any version).
- transformers==4.57.6 (2026-01-16): the newest 4.x, chosen over 5.x for the image's pre-release torch. From 5.20.0 (2026-10-15; newest 5.22.2) `is_torch_available` disables PyTorch when `version.parse(torch) < 2.6.0`, which 2.6.0a0 fails; earlier 5.x releases check a lower minimum (5.0.0: 2.2, 5.5.0: 2.4, 5.19.0: 2.5) and were not tried here (5.19.0 also needs huggingface-hub>=1.31). 4.57.6 needs torch>=2.1, exports `PretrainedConfig` (imported by open_clip 3.3.0's `hf_model.py`) and ran the CPU smoke test above. Brings tokenizers >=0.22,<=0.23.
- huggingface-hub==0.36.2 (2026-02-06): the newest release below 1.0 (transformers 4.57.6 requires >=0.34,<1.0).

## Pitfalls

- Job 2554 (dev, 2026-11-14) stopped in `load()`: transformers 4.57.6 imports `TransformGetItemToIndex` from `torch._dynamo._trace_wrapped_higher_order_op`, which the image's 2.6.0a0 lacks (it has the class in `torch._higher_order_ops.flex_attention`); open_clip's `hf_model.py` turns the ImportError into "Please `pip install transformers`". `common/torch_compat.py` aliases it; the CPU smoke test with torch 2.6.0 (release) could not show this.
