Model structure (from the code; the checkpoint itself was not seen). `load_model` builds `MedMLLMConfig` from `<checkpoint>/args/config.json`, which loads the configs of the base models by name (`AutoConfig.from_pretrained(..., trust_remote_code=True)`); `MedMLLMForConditionalGeneration` then loads the Phi-3 tokenizer, SigLIP's image processor and the full M3D-CLIP from the Hub, and `load_model` replaces their weights from `llm/`, `vision2d_model/`, `vision2d_connector/`, `vision3d_model/`, `vision3d_connector/` of the checkpoint (layout of `training_recipe/base.py`). The training scripts set `exp_id 4` (SigLIP on every slice, TG-IS scores against the question), `llm_type phi3` (microsoft/Phi-3-mini-128k-instruct), `vision2d google/siglip-large-patch16-256`, `vision3d GoodBaiBai88/M3D-CLIP`, connector `spatial_pooling_score15_mlp2x_gelu`, `llm_max_length 768`, `llm_attn_implementation flash_attention_2`, `tokenizer_use_fast False`, full fine-tuning (so no `adapter_config.json`, no peft). Visual tokens: 256 from M3D-CLIP (8×16×16 patches, 2×2×2 average pooling) + 256 from SigLIP (16×16 patches, TG-IS-weighted sum over the 32 slices); with the prompt (67-83 text tokens for the questions of `common/qna.py`, counted with the tokenizer below) at most 595 embeddings, under the 768 at which `prepare_inputs_for_multimodal` truncates. Every one of these names must be in the offline HF cache, hence the five repos in `env.sh` (the brief listed only the checkpoint): bert-base-uncased because M3D-CLIP's `__init__` loads it, twice per load.

Then `DataCollatorForMultiModalDataset(tokenizer=model.tokenizer, mode="eval")`, the device/dtype loop of Stage 4, `model.generate(**batch, do_sample=False, num_beams=1, pad_token_id=model.tokenizer.pad_token_id, eos_token_id=model.tokenizer.eos_token_id)` (it returns `(LLM output, TG-IS scores)`) and `model.tokenizer.batch_decode(..., skip_special_tokens=True)[0]`.
- The prompt "<image3d>\n" + "{question} Choices: A. ... B. ... C. ... D. ..." is M3D's close-ended VQA format (`multi_dataset.py`: `question + ' ' + "Choices: A. {} B. {} C. {} D. {}"`, answer `"{letter}. {text}"`; the Med-2E3 scorer checks `answer_choice + "."` in the output), after the image token as in the README's examples. The phi template makes it "<system> USER: <image3d>\n{question} ASSISTANT:".

Deviations:
- Decoding: `max_new_tokens=16` (global constraints) instead of `max_length=768`; `temperature` not passed (0 in the scripts = greedy); `return_dict_in_generate=True, output_scores=True` added, so the text comes from `output.sequences`.
- The item is built in memory: `MultiModalDataset` itself is not used, because its `__init__` reads a JSON file and loads the question tokenizer with the hard-coded `cache_dir="/mnt/nfs_share/shiym/ckpts/cache_dir_hf"`. The question tokenizer is loaded with the same arguments from the default cache.
- `local_checkpoint`: `load_model` gets a temporary folder with symlinks to every top-level entry of the snapshot and its own `args/config.json`, the checkpoint's with `cache_dir_hf` set to null (default cache, `HF_HOME`). `MedMLLMConfig` passes the stored value to `AutoConfig.from_pretrained` before `load_model` overrides it; the authors' value is presumably their cache folder (the path hard-coded in `dataset.py`), where an offline job finds nothing.
- Attention: the training scripts store `llm_attn_implementation flash_attention_2` in the config. If `transformers.utils.is_flash_attn_2_available()` is false in the job, `local_checkpoint` writes `llm_attn_implementation: "sdpa"`, which Phi-3 accepts in transformers 4.45.2 (`_supports_sdpa = True`; it is False up to 4.44, where only `"eager"`, the commented-out fallback in `src/inference.py`, would work). No flash-attn install.
- Python 3.12: the conversation templates (`src/data/template/*.py`) use formatter instances as dataclass field defaults, which Python >= 3.11 rejects ("mutable default ... use default_factory"), so `src.inference` does not import in the image as published (the README asks for Python 3.10). `preload_formatters` imports `formatter.py` under its package name first and gives `EmptyFormatter`/`StringFormatter` the identity hash: the 3.10 behaviour (one shared default instance per template class). The repo's files are not modified.
- Blank control: `CropForeground` finds no voxel > 0 in an all-zero volume and crops to an empty array, which `Resize` rejects (checked: RuntimeError). `model_volume` passes such a volume unchanged (it is already 32×256×256); every other volume goes through the repo's transform.
- TG-IS question projection: after `load_model`, `text_mlp` is loaded from the checkpoint when it has it (see the TG-IS note below); `torch.manual_seed(0)` before loading fixes the random initialisation for the case it does not.

TG-IS question projection (`text_mlp`): `Connector.load_model` (`connector/base.py`) restores only the `_connector.*` weights (`get_w(weights, "_connector")`). `SpatialPoolingScore15Connector` also has `text_mlp` (Linear 768 → 3072), which projects the question embedding for the slice scores. Training saves it (`training_recipe/base.py` saves every connector parameter into `vision3d_connector/pytorch_model.bin`), but the published loader leaves it at its random initialisation (`_init_weights`: normal with the LLM's `initializer_range`), so the 2D branch's slice weights would come from a random projection of the question. What we do: after `load_model`, `load()` reads `<checkpoint>/vision3d_connector/pytorch_model.bin` (`torch.load(..., map_location="cpu")`, as `Connector.load_model` does) and, if it has `text_mlp.*` keys, loads exactly those into `model.vision3d_connector.text_mlp` with `strict=True` (`load_text_mlp`; keys selected the way `get_w` selects `_connector`). This is the trained model as saved, at the cost of departing from the published inference path on this one module. If the file or the keys are missing, the initialisation after `torch.manual_seed(0)` stays, the same at every load. `load()` prints "med-2e3: TG-IS text_mlp from checkpoint|random_seed0", and every scan's details carry `text_mlp_source` (`checkpoint` or `random_seed0`) next to the per-field logs. Checked with torch 2.6.0 (CPU) on a state dict with the connector's parameter names saved by `torch.save`: the trained weights are copied, a dict without the keys gives `random_seed0`, and a partial `text_mlp` entry raises.

Best guesses (not verifiable here):
- TG-IS question text: the eval JSONs (with their `"question"` field) are not published; `_generate` passes the question with its choices, without the image token.
- `args/config.json` holds the training scripts' Hub names (`microsoft/Phi-3-mini-128k-instruct`, `google/siglip-large-patch16-256`, `GoodBaiBai88/M3D-CLIP`) as `_name_or_path`, `exp_id` 4 and the score15 connector. If it holds local paths of the authors' machine, `local_checkpoint` must map them too.
- Letter probabilities: softmax of the first generated position's scores at the ids of "▁A", "▁B", "▁C", "▁D", renormalised over the four. The ids are what the tokenizer gives for "ASSISTANT: X" after the ids of "ASSISTANT:", the token that follows "ASSISTANT:" in the trained answers "ASSISTANT: C. ...". Checked with the Llama-2 SentencePiece model Phi-3-mini's tokenizer is built on (llama2.c's `tokenizer.model`, as `LlamaTokenizer(legacy=False, add_bos_token=False)`): ids 319, 350, 315, 360; the eval prompt's ids are a prefix of the trained prompt's ids, and the next trained token is "▁C".

Orientation and intensities:
- M3D-Cap arrays (`m3d_cap_data_prepare.py`): Radiopaedia display images (grey, /255) sorted by file number and stacked along axis 0, min-max scaled, `CropForeground`, `Resize([32, 256, 256])`, saved as (1, 32, 256, 256) in [0, 1]. Depth is the series' own plane and order (the README's example file is `ct_case/005537/Sagittal_lung_window.npy`, so sagittal series are in the data too); in-plane as displayed, which for axial series is the radiological display: rows anterior → posterior, columns patient right → left.
- Med-2E3's loader (`np.load` → `Vision3DPreprocess`) does not reorient; `prepare_inputs_for_multimodal` takes the 32 slices along the first spatial axis for SigLIP (each grey slice repeated to 3 channels, no SigLIP normalisation).
- Ours: `common.volume.load_canonical` (D feet → head, H front → back, W patient right → left) → `to01` → `resize(·, (32, 256, 256))` → `[None]`, no flip. The in-plane layout matches M3D's axial display images; no source fixes a depth direction (M3D keeps file order). `test_input_shape` pins this.
- `to01` gives [0, 1] like M3D's arrays: MRI by the 0.5/99.5 percentiles, CT-RATE by the [-1000, 1000] HU window (the paper's CT-RATE preprocessing).

Pins (`requirements.txt`):
- transformers==4.45.2. Neither the repo nor the README names a version. MedM-VL pins 4.42.4, which cannot build Phi-3-mini-128k-instruct's current config: its native Phi3 accepts only rope scaling "su"/"yarn" ("longrope" from 4.43.0). From 4.52 transformers refuses to `torch.load` a `.bin` file unless torch >= 2.6, and the image's 2.6.0a0 is a pre-release below 2.6 (`check_torch_load_is_safe`); Med-2E3's checkpoint folders hold `torch.save` `pytorch_model.bin` files. 4.45.2 lies inside that window, came out on 2024-10-07 (before arXiv v1, November 2024), supports SDPA for Phi3, and is the version the scratch checks below ran. PyPI: `requires_python >=3.8.0`, tokenizers >=0.20,<0.21 (0.20.3, abi3 wheels), huggingface-hub >=0.23.2,<1.0.
- monai==1.3.2: MedM-VL's `requirements.txt`. M3D-CLIP's remote code passes `pos_embed` to monai's `PatchEmbeddingBlock`, deprecated since 1.2 with `removed="1.4"` (raises from 1.4 on), so monai must stay below 1.4. monai 1.3.2 imports `distutils` (`utils/misc.py`), which Python 3.12 no longer ships; it imports through setuptools' distutils shim (checked in the scratch environment).
- sentencepiece==0.2.0: MedM-VL's `requirements.txt`; the Phi-3 tokenizer loads as the slow `LlamaTokenizer` (`tokenizer_use_fast False`); cp312 wheels. With `legacy` false it also needs protobuf (checked: it fails without), which is not listed: the image ships TensorBoard 2.16.2, which depends on protobuf.
- einops==0.8.2: `connector/pooling.py` imports `einops.layers.torch.Rearrange`; no version named anywhere; the newest release.
- open_clip_torch==3.3.0, timm==1.0.26: `vision2d/clip.py` imports `open_clip` at module level, and the vision2d factory imports it even though SigLIP is used. 3.3.0 is the newest release the image's torch satisfies (4.x requires torch>=2.6, which 2.6.0a0 does not meet); the same pair as models/hlip in the same image.
- huggingface-hub==0.36.2: `load()` calls `snapshot_download`; the newest release below 1.0 (transformers 4.45.2 requires <1.0).
- Not listed: flash-attn (the image's, if any), peft (only for a LoRA checkpoint), deepspeed and accelerate (training only), torch/torchvision (the image's).
- `uv pip compile` for Python 3.12 with `torch==2.6.0`, `torchvision==0.21.0`, `numpy==1.26.4` as constraints resolves these pins.

Scratch checks (CPU, Python 3.13 venv with torch 2.6.0 and the pins above, sentencepiece 0.2.1 for 3.13; nothing of it is in the repo):
- `from src.inference import load_model` (the whole import chain) works after `preload_formatters` and fails with "mutable default" without it.
- The phi template on the Llama-2 SentencePiece model gives "A chat between ... questions. USER: <image3d>\nWhat is the modality of this image? Choices: A. MRI B. CT C. X-ray D. Ultrasound ASSISTANT:" (71 ids, the image token at position 34).
- `Vision3DPreprocess` on `predict`'s array returns a (1, 32, 256, 256) float32 tensor; on a blank array it raises in `Resize` (hence `model_volume`).
- `_generate` with a stand-in model, on a real and a blank volume: the repo's collator gives `input_ids` (1, 71) = the template's ids, a boolean all-true `attention_mask`, `questions`/`questions_mask` (1, 512), `vision3d` (1, 1, 32, 256, 256) bf16, `vision2d`/`vision3d_224` None; decoding and letter probabilities as intended.
- A small random native `Phi3ForCausalLM` with "longrope" scaling (eager and SDPA), called as Med-2E3's `generate` calls it (`inputs_embeds`, a float attention mask, `labels`, `use_cache=True`, plus our flags): `sequences` holds only the 16 new tokens, `scores[0]` equals the logits of the last prompt position, and the first token is their argmax.

The repo prints the TG-IS scores ("scores: ...") at every `generate` call, so the job log is long.
